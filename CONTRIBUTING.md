# Contributing

Keep each pull request independently reviewable.

1. Synchronize your fork with the upstream default branch.
2. Create one short-lived branch per change.
3. Verify the effective Git author before committing.
4. Add tests or validation when behavior changes.
5. Explain the problem, the chosen approach, and verification in the pull request.
6. Avoid unrelated formatting or generated-file churn.

A contribution is ready to merge when its scope is clear, checks pass, attribution is correct, and the change can be reverted independently.
