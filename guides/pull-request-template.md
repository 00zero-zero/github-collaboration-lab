# Pull request template design

A pull request template should capture review-critical context without turning every contribution into paperwork.

Ask for the problem being solved, the scope of the change, validation performed, known risks, and any migration or compatibility impact. Keep optional sections clearly optional.

Avoid fields that duplicate information already visible in the diff or CI. Templates should improve reviewer decision quality, not maximize form completion.

For repositories with several change types, a small set of focused templates is often clearer than one very large universal template.
